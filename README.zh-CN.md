# 摇一摇找鼠标（Windows）

**把 macOS 的「晃鼠标 → 指针变大」搬到 Windows 10/11。**

4K 屏、多显示器上找不到鼠标指针？抓起鼠标晃两下——指针会变成一只**实心、放大 3 倍的大箭头**，
停留一会儿再缩回原样。

仅支持 Windows，需要 Python 3.8+，**零第三方依赖**（纯 `ctypes` 调 Win32，不需要 `pip install`）。

![演示](docs/demo.gif)

<sub>晃一下鼠标 → 指针变成实心 3 倍大箭头 → 约 1 秒后缩回原样。</sub>

---

## 为什么做这个

macOS 一直有这个功能。Windows 的「辅助功能 → 鼠标指针大小」只能全局永久放大，
意味着指针在**任何时候**都是巨大的。这个工具只在**你需要的时候**放大一下。

## 快速开始

1. Windows 10 或 11，装好 Python 3.8+（安装时勾选 **Add python.exe to PATH**）
2. 下载本仓库（`Code → Download ZIP`）或 `git clone`
3. 双击 **`start.bat`**
4. 晃动鼠标

不用安装、不用管理员权限、不注册服务。要退出按 `Ctrl + Alt + Q`，或双击 `stop.bat`。

| 文件 | 作用 |
| --- | --- |
| `start.bat` | 后台启动（无控制台窗口） |
| `start-debug.bat` | 带控制台启动，会打印每一次识别到的晃动 |
| `stop.bat` | 退出，并强制还原系统鼠标指针 |
| `autostart-on.bat` | 开启登录自启（仅当前用户，无需管理员） |
| `autostart-off.bat` | 关闭登录自启 |
| `shake_cursor.pyw` | 程序本体 |

## 怎么判断你在「晃」

不是简单的位移阈值。两个轴各跑一个小状态机，统计**方向反转**：

- 反向只要够 `SHAKE_MIN_RUN`（12px）就算一次折返，**不需要吃掉整条腿**；
- 折返发生在 **1 秒的动作时间**内，攒够 **3 次**即触发；
- 摆幅要**沿一个方向**：主导轴至少是对另一轴的 1.8 倍，否则当画圈处理。

所以缓慢拖动、画圈、手抖、慢慢来回荡**都不会**误触发。

### 为什么强调"动作时间"，还有触控板

这是 1.4.0 修的核心问题。触控板的真实节奏是：**滑一下 → 抬手指（150~300ms 没有位移）→ 滑回来**。

旧版本按**墙上时间**统计窗口，抬手指那段停顿也算进 0.6 秒里，结果滑完四下只攒到 1~2 次折返，
表现就是"我明明滑了好几下，它没反应"。现在窗口只累计**确实在动**的时间，
停顿不计入；只有连续静止超过 1.2 秒才认为这次手势结束了、清零重来。

顺带修掉一个老问题：画圈时两轴都是正弦波形，单轴看和晃动几乎一样，以前会误触发。
现在要求运动是**近似直线**的（主导轴摆幅 ≥ 另一轴的 1.8 倍）。代价是斜着晃不会被识别，
但真人几乎不会斜着晃鼠标。

### 触发灵敏度

托盘菜单 → **触发灵敏度**（或 `settings.json` 里的 `sensitivity`）：

| 档位 | 单程门槛 | 折返次数 | 时间窗 | 适合 |
| --- | --- | --- | --- | --- |
| `low` | 16px | 3 | 0.45s | 觉得容易误触，只要最明确的晃 |
| `normal` | 12px | 3 | 1.0s | **默认**，鼠标和触控板都能用 |
| `high` | 8px | 3 | 1.3s | 手指力度轻 / 触控板滑不太动 |

注意三档都保持 **3 次折返**：次数降到 2 时历史太短，"主导轴"判定会失效，
画圈又会被误判成晃动——这个边界在 `tools/test_shake.py` 里验证过。

## 参数调整

打开 `shake_cursor.pyw`，常量都在文件开头：

| 常量 | 默认 | 含义 |
| --- | --- | --- |
| `PEAK_SCALE` | `3.0` | 放大倍数 |
| `GROW_SEC` | `0.13` | 放大耗时 |
| `HOLD_SEC` | `0.72` | 保持大号的时长 |
| `SHRINK_SEC` | `0.26` | 缩回耗时 |
| `SHAKE_MIN_RUN` | `12` | 单程最小位移（px），调大 = 更难触发（`normal` 档的值） |
| `SHAKE_WINDOW` | `1.00` | 折返统计时间窗（**动作时间**，秒） |
| `SHAKE_REVERSALS` | `3` | 时间窗内需要的折返次数 |
| `PAUSE_BUDGET` | `1.20` | 连续静止超过这么久就清零（触控板抬手指不算） |
| `AXIS_DOMINANCE` | `1.8` | 主导轴摆幅倍数，用来挡掉画圈 |
| `HIDE_SYSTEM_CUR` | `True` | 放大时是否隐藏真指针（见下文） |
| `OUTLINE_RATIO` | `0.08` | 白描边粗细（相对箭头高度） |

改完保存，退出程序重新启动生效。

## 更新

直接替换 `shake_cursor.pyw`（或者 `git pull`）就行。运行中的实例会发现文件变了，
等 1.5 秒确认稳定后，启动一个新进程（新进程会先等旧进程退出，避免抢单实例锁），
旧进程随即退出——**不用手动重开**。更新不会动你的 `settings.json`。

### 外观

两个参数同时写在 `settings.json` 里，重启后保留，也可以脚本化改：

```json
"appearance": { "scale": 3.0, "color": "#000000" }
```

`scale` 会被收敛到 1.5–6.0。改动后会用新参数重建帧缓存（约 40–160 ms（21–41 帧，倍数越大帧越多、位图也越大））并闪一次，让你立刻看到效果。箭头始终保留白色描边，
所以深色箭头在深色背景上依然看得清。

## 场景感知

打游戏、全屏看片、投屏演示的时候，指针突然变大是最烦的——挡视野、还抢注意力。
所以在「已经识别到摇动、即将播放动画」的那一刻做三层判断（125Hz 轮询主循环完全不受影响）：

| 层 | 信号 | 能识别什么 |
| --- | --- | --- |
| 1 | `SHQueryUserNotificationState` | Windows 自己压制通知用的那个 API：`QUNS_RUNNING_D3D_FULL_SCREEN` = 独占全屏游戏，`QUNS_BUSY` = 有全屏应用在跑，`QUNS_PRESENTATION_MODE` = 演示中 |
| 2 | 前台窗口是否铺满显示器 | 兜底，专治"不更新系统状态"的程序；**最大化窗口不算**（它只铺满工作区） |
| 3 | 进程黑名单 / 白名单 | 你自己的例外清单 |

多屏细节：全屏窗口在 A 屏、光标在 B 屏时**照常放大**——你并不在那个全屏应用里面。

配置在 `settings.json`（首次运行自动生成在同目录）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `suppress_in.d3d_fullscreen` | `true` | 独占全屏游戏不响应 |
| `suppress_in.fullscreen_app` | `true` | 前台窗口铺满显示器时不响应 |
| `suppress_in.busy` | `true` | 系统报"忙"时不响应（覆盖全屏视频） |
| `suppress_in.presentation` | `true` | 演示 / 投影模式不响应 |
| `suppress_in.locked` | `true` | 锁屏时不响应 |
| `process_blacklist` | `game.exe, steam.exe, …` | 这些进程一律不响应 |
| `process_whitelist` | `[]` | 这些进程即使在游戏里也响应 |

文件改动后**自动重载**，不用重启；白名单优先于黑名单。

## 实现原理

1. **识别** —— 以约 125Hz 轮询 `GetCursorPos`，把位移喂给两个逐轴折返计数器（见上）。
2. **隐藏真指针** —— 用 `CreateIconIndirect` 造一个全透明光标，再用
   `SetSystemCursor(OCR_NORMAL)` 临时替换系统箭头。**只替换普通箭头**，I 型光标和手型光标不受影响。
3. **画放大的指针** —— 一个 `WS_EX_LAYERED` 的点击穿透窗口，用 `UpdateLayeredWindow`
   做逐像素 alpha 合成。箭头是经典多边形，用 GDI 在 **4 倍超采样**下填充、再
   `StretchBlt(HALFTONE)` 降采样，所以边缘干净不糊。21 个尺寸在启动时一次性预渲染
   （约 30ms），动画时只换帧并跟随鼠标。
4. **安全兜底** —— `SetSystemCursor` 最坏的后果是「指针一直看不见」。所以程序会拉起一个
   极小的**看门狗子进程**，阻塞在 stdin 管道上：主进程无论因为什么原因退出（正常退出、
   崩溃、被任务管理器强杀），管道一断，看门狗立刻 `SystemParametersInfo(SPI_SETCURSORS)`
   把指针还原。`stop.bat` 是额外的手动开关。

## 常见问题

**鼠标指针不见了/看不见了。** 双击 `stop.bat`，即使程序没在运行它也能还原系统指针。

**晃了没反应。** 用 `start-debug.bat` 启动，看控制台输出：每次识别到晃动都会打印坐标。
如果一直只有 "running" 没有触发，晃得再快一点/幅度再大一点，或者调小
`SHAKE_MIN_RUN` / `SHAKE_REVERSALS`。

**提示找不到 Python。** 去 [python.org](https://www.python.org/downloads/) 装 3.8+，
安装时勾选 "Add python.exe to PATH"。

**会不会同时跑起来两份？** 不会。程序持有命名互斥量，第二个实例会直接退出。

**改了代码没生效。** 正在运行的实例内存里还是旧代码，`Ctrl + Alt + Q` 退出后重新启动。

## 已知限制

- 只替换**普通箭头**。指针停在输入框（I 型）或链接（手型）上时，系统光标保持原形，
  这时会看到大箭头出现在旁边。这是有意的取舍——不去掩盖指针当前的含义。
- 独占全屏的游戏、以及自绘/缓存光标的程序里，叠加窗口可能不显示。
- 仅 Windows。macOS 自带此功能；Linux 需要合成器层面的实现。
